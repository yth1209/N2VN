# plan.md — 씬 내 캐릭터 화면 배치 개편

> proposal.md 요구사항 기반으로 작성된 서비스 기획서.
> 개발 상세는 development.md 참조.

---

## 1. 배경 및 문제 인식

현재 비주얼 노벨 플레이어는 각 대사 단위로 "이 캐릭터가 등장하는가(isEntry) / 퇴장하는가(isExit) / 어느 위치에 있는가(position)"를 대사 개별 속성으로만 관리한다.

이 방식은 다음과 같은 상황에서 화면 상태를 정확히 표현하지 못한다:

### 문제 시나리오

| 상황 | 현재 결과 | 기대 결과 |
|---|---|---|
| 혼자 있던 캐릭터가 center에 있다가 새 캐릭터 등장 | 기존 캐릭터의 position이 여전히 center로 남아 위치 충돌 | 기존 캐릭터가 자동으로 left/right로 재배치 |
| 3명 중 2명이 동시에 퇴장 | 마지막 1명의 위치가 left/right로 고정된 채 남음 | 퇴장 후 남은 1명이 자동으로 center로 이동 |
| 군중 등 집단 캐릭터 등장 | 기존 캐릭터와 위치 충돌 가능 | 집단 캐릭터 등장 시 기존 캐릭터 전원 퇴장 처리 |

**근본 원인:** 각 대사는 자신의 등장·퇴장 여부만 알 뿐, "이 대사가 출력되는 순간 화면에 누가 어디에 있는지"를 전체적으로 알 수 없다.

---

## 2. 목표

각 대사가 출력되는 순간의 **화면 전체 상태(currentScreen)**를 명시적으로 정의한다.

- 대사 하나하나에 "현재 화면에 있는 모든 캐릭터 목록"과 각자의 위치·감정·행동을 함께 기록한다.
- 플레이어는 대사를 출력할 때마다 currentScreen을 기준으로 화면을 재구성한다.
- LLM이 씬을 분석할 때부터 올바른 화면 상태를 계산하여 저장한다.

---

## 3. 사용자 경험 변화

### 3.1 캐릭터가 등장할 때

- 혼자 있을 때: 화면 정중앙(center)에 표시된다.
- 2인 동시: 각자 좌(left) / 우(right)로 나뉘어 표시된다.
- 3인 동시: 좌(left) / 중앙(center) / 우(right)로 나뉘어 표시된다.
- 기존 캐릭터가 있을 때 새 캐릭터가 추가되면, 기존 캐릭터의 위치도 자연스럽게 재배치된다.

### 3.2 캐릭터가 퇴장할 때

- 한 명이 퇴장하면 남은 캐릭터들이 자동으로 최적 위치로 재배치된다.
- 여러 명이 동시에 퇴장해도 남은 캐릭터가 올바르게 배치된다.

### 3.3 집단 캐릭터(군중, 단체)가 등장할 때

- 집단 캐릭터가 등장하는 순간 기존 화면의 모든 캐릭터가 자동으로 퇴장 처리된다.
- 집단 캐릭터는 항상 화면 중앙에 단독으로 표시된다.
- 집단 캐릭터가 화면에 있는 동안 다른 캐릭터는 등장할 수 없다.

### 3.4 화자(발화자)가 아닌 캐릭터의 감정·행동 표현

- 현재: A가 대사를 말하는 동안 화면에 있는 B의 표정·행동은 업데이트되지 않는다.
- 변경 후: 매 대사마다 화면의 모든 캐릭터 감정·행동이 명시되어, A가 말할 때 B의 표정 변화도 자연스럽게 반영된다.

## 4. 화면 배치 규칙 (사용자 관점)

| 화면 인원 | 배치 방식 |
|---|---|
| 1명 | 정중앙(center) |
| 2명 | 좌(left) + 우(right) |
| 3명 | 좌(left) + 중앙(center) + 우(right) |
| 4명 이상 | 불가 — 기존 캐릭터 중 가장 비활성인 캐릭터를 퇴장시켜 3명 이하로 유지 |

> **내레이터**: 캐릭터 인원수에 포함되지 않으며 항상 center.

---

## 5. 적용 범위

- **신규 소설**: 이번 개편된 방식으로 생성된 모든 소설에 적용된다.
- **기존 소설**: 마이그레이션 없이 구버전 그대로 유지된다. (기존 소설 데이터 영향 없음)

---

## 6. 주요 변경 대상

| 대상 | 변경 내용 |
|---|---|
| 씬 파싱 (LLM) | 각 대사에 currentScreen 배열 추가 출력 |
| S3 scenes.json | currentScreen 포함 신규 포맷으로 저장 |
| 프론트엔드 플레이어 | currentScreen 기반 화면 재구성 로직으로 교체 |

---

## 7. 기대 효과

- 연출 정확도 향상: LLM이 명시적으로 화면 상태를 계산하므로 위치 오류가 크게 감소한다.
- 복잡한 씬 표현 가능: 다수 캐릭터의 동시 등·퇴장, 집단 씬 등 기존에 표현하기 어려웠던 연출이 가능해진다.
- 플레이어 단순화: 플레이어가 isEntry/isExit를 추적하여 화면 상태를 역산할 필요 없이, 매 대사마다 currentScreen을 그대로 렌더링하면 된다.
