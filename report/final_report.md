# N2VN: Novel-to-Visual-Novel 자동 변환 파이프라인

**과제연구 최종 보고서**  
2026년 5월 30일

---

## 1. 연구 목적 (Problem Statement)

본 연구의 목적은 텍스트 기반의 소설을 캐릭터 일러스트, 배경 이미지, BGM 및 대화형 UI가 결합된 '비주얼 노벨(Visual Novel)' 형태로 자동 변환하는 **N2VN(Novel-to-Visual-Novel) Pipeline**을 개발하는 것이다.

비주얼 노벨은 독자에게 캐릭터 일러스트, 배경 이미지, 배경음악, 타이프라이터 대사 연출이 결합된 높은 몰입감의 스토리 경험을 제공한다. 그러나 이를 제작하기 위해서는 일러스트레이터, 프로그래머, 음악 프로듀서 등 다수의 전문 인력이 필수적으로 투입되어야 하며, 이로 인해 제작 진입장벽이 매우 높다. 현재 비주얼 노벨 콘텐츠는 주로 서브컬처 게임에 종속된 형태로 서비스되고 있어, 독자는 순수하게 스토리를 감상하기 위해 원치 않는 게임 플레이(전투, 스펙업, 피로도 시스템 등)를 강제당하는 구조적 피로감을 겪는다. 또한 스토리 업데이트까지 짧게는 6주에서 길게는 수개월이 소요되는 심각한 공급 병목이 존재한다.

본 프로젝트는 이러한 한계를 허물고, 텍스트 중심의 소설 IP를 고부가가치의 시청각 콘텐츠로 손쉽게 확장할 수 있는 자동화 시스템을 구축하고자 한다. 이를 통해 궁극적으로 누구나 '주간 연재' 주기로 비주얼 노벨을 생산하고 소비할 수 있는 '웹툰형 비주얼 노벨 플랫폼'의 기반 기술을 확립하는 것을 최종 목표로 한다.

## 2. 연구 배경 (Motivation and Background)

### 2.1 웹소설 시장과 멀티미디어 확장의 한계

웹소설 시장은 '회빙환(회귀, 빙의, 환생)' 등의 메가 트렌드를 중심으로 폭발적인 성장을 이루며 강력한 대중성을 입증했다. 텍스트 매체 특유의 낮은 창작 진입장벽 덕분에 다수의 작가들이 매일 새로운 스토리 콘텐츠를 쏟아낼 수 있는 빠른 공급 구조가 확립되었기 때문이다.

그러나 이러한 웹소설 IP를 시청각적 몰입감이 뛰어난 비주얼 노벨로 변환·확장하려는 시도는 번번이 좌절되어 왔다. 기존의 Pinto와 같은 비주얼 노벨 UGC(User Generated Content) 플랫폼들은 유저에게 텍스트 연출을 위한 샌드박스 엔진만을 제공했을 뿐, 그 안에 들어갈 핵심 리소스인 일러스트, 배경, 음악 등의 수급 문제는 오롯이 창작자 개인에게 떠넘겼다. 글쓰기에 특화된 작가들이 고품질의 멀티미디어 에셋을 자체적으로 조달하는 것은 비용과 시간 측면에서 한계가 명확하다. 즉, '텍스트의 빠른 생산 속도'와 '시청각 에셋의 물리적인 제작 속도' 사이의 치명적인 불균형이 비주얼 노벨의 대중화를 가로막는 가장 큰 병목이다.

### 2.2 생성형 AI의 등장과 기술적 과제

최근 생성형 AI 기술이 비약적으로 발전하며 이 리소스 조달 문제를 해결할 가능성이 열렸다. 그러나 비주얼 노벨 서비스에 AI를 전면 도입하기 위해서는 **캐릭터의 시각적 일관성(Visual Consistency) 유지**라는 핵심적인 기술적 과제를 극복해야 한다.

컴퓨터 그래픽스 및 비전 학계에서는 Diffusion Model에서 초기 노이즈를 고정하고 Cross Attention을 제어하여 이미지의 구조적 일관성을 보존하는 방법론[1]이 핵심 전제 조건으로 자리 잡았다. 나아가 단일 텍스트 프롬프트만으로 모델의 Fine-tuning 없이 캐릭터의 정체성을 자동 추출하고 유지하려는 연구[2]가 최상위 학회에서 활발히 논의되는 등, 시각적 일관성 확보는 현재 생성형 AI 분야의 가장 쟁점이 되는 화두이다.

본 연구는 이러한 최신 학술적 흐름을 바탕으로, 기존 UGC 플랫폼의 물리적인 에셋 수급 한계와 생성형 AI 도입의 기술적 장벽을 동시에 해결하고자 한다. LLM 기반의 맥락 추론부터 Image/Audio 생성 API까지 모두 엮어낸 Pre-generation Pipeline을 구축함으로써, 소설 텍스트 입력만으로 즉각적인 멀티미디어 렌더링이 가능한 완전 자동화 구조를 제안한다.

## 3. 연구 방법 (Design and Implementation)

### 3.1 고차원 시스템 설계

N2VN 파이프라인은 다섯 개의 AI Agent를 이벤트 버스로 연결한 **멀티 에이전트 파이프라인(Multi-Agent Pipeline)** 구조로 설계되었다.

```
novel.txt (S3 업로드)
    │
    ▼
[Agent 1] Gemini 3.5 Flash — 캐릭터 파싱
    │  (Character Bible 생성: 이름, 성별, 외모 묘사, 화풍 키)
    ▼
[Agent 2] Gemini 3.5 Flash — 씬 파싱
    │  (배경, BGM, 대화 스크립트, 화면 상태 추출 → scenes.json)
    │
    ├──────────────────────────────────┐──────────────────┐
    ▼                                  ▼                  ▼
[Agent 3] Gemini Image             [Agent 4] Gemini Image  [Agent 5] Lyria 3 Clip
  캐릭터 이미지 생성 (병렬)           배경 이미지 생성 (병렬)  BGM 생성 (병렬)
    │                                  │                  │
    └──────────────────────────────────┘──────────────────┘
                    │ 모든 에셋 완료
                    ▼
        VN Script → 프론트엔드 플레이어
```

백엔드는 NestJS 11(TypeScript) 기반으로 구현되었으며, `EventEmitter2`를 통한 이벤트 버스로 각 Agent 간 비동기 연결을 실현했다. `SCENES_DONE` 이벤트를 캐릭터 이미지·배경 이미지·BGM 핸들러 세 곳이 동시에 구독하여, 씬 파싱 완료 후 세 생성 파이프라인이 병렬로 실행된다.

기술 스택은 다음과 같다.

| 구성 요소 | 기술 |
|---|---|
| 서버 프레임워크 | NestJS 11 (TypeScript) |
| ORM / DB | TypeORM 0.3 + MariaDB (AWS RDS) |
| 이벤트 버스 | @nestjs/event-emitter (EventEmitter2) |
| LLM | Google Gemini 3.5 Flash (LangChain + StructuredOutputParser) |
| 이미지 생성 | Gemini Image API — gemini-3-pro-image-preview (Batch API) |
| 오디오 생성 | Google Lyria 3 Clip |
| 배경 제거 | Photoroom API |
| 클라우드 스토리지 | AWS S3 (AES256 암호화) |
| 스키마 검증 | Zod |

### 3.2 LLM 기반 메타데이터 추출 파이프라인

#### 3.2.1 캐릭터 파싱 (Character Parsing)

소설 텍스트에서 등장인물의 외모 묘사를 이미지 생성용 프롬프트로 변환하는 단계다. LangChain의 `StructuredOutputParser`가 Zod 스키마에서 JSON 포맷 지시문을 자동 생성하여 프롬프트에 삽입하고, Gemini 3.5 Flash(`temperature: 0.1`)가 구조화된 JSON을 반환한다.

핵심 설계 원칙 두 가지를 적용했다.

**감정·외모 엄격 분리**: `look` 필드에 표정이나 감정 관련 묘사를 포함하는 것을 명시적으로 금지했다. 이를 통해 하나의 Character Bible로 10가지 감정 이미지를 생성할 수 있다. 소설 내 외모 묘사가 충분하지 않은 경우 캐릭터의 직업·성격·장르 관습을 기반으로 시각적 디테일을 능동적으로 보완하도록("CREATIVE INFERENCE") 프롬프트에 명시했다.

**외모 묘사 5요소 강제**: `look` 필드를 (1) 나이/성별, (2) 헤어스타일, (3) 얼굴/신체, (4) 의상, (5) 소품/무기의 조합으로 고정하여 이미지 생성 품질을 일관되게 유지했다.

#### 3.2.2 씬 파싱 (Scene Parsing)

소설 원문 전체와 캐릭터 목록을 컨텍스트로 받아, 장소·시간 전환을 기준으로 Scene을 분할하고 각 Scene마다 배경, BGM, 대화 스크립트를 추출한다. 대화 스크립트에는 화자 ID, 원문 대사, 감정 상태, 화면 위치(left/center/right), 캐릭터 액션(IDLE/ATTACK/SHAKE)이 포함된다.

**tempId 패턴**: LLM이 단일 호출 내에서 신규 배경·BGM을 `new_bg_1`, `new_bgm_1` 형식의 임시 ID로 선언하고 씬에서 참조하면, 코드에서 실제 UUID로 치환하는 방식을 설계했다. 이를 통해 LLM 응답의 자기 참조(self-reference) 문제를 해결했다.

**최대 3인 화면 제약**: 화면에 동시에 등장하는 캐릭터를 최대 3명으로 제한하고, 4번째 캐릭터 등장 시 가장 비활성 캐릭터를 퇴장시키도록 프롬프트에서 강제했다.

### 3.3 이미지 생성 파이프라인

#### 3.3.1 캐릭터 이미지: DEFAULT-First Image-to-Image 전략

초기 계획에서는 Seed 고정 방식으로 캐릭터 일관성을 확보할 것을 계획했다. 그러나 Seed 고정은 동일한 프롬프트로 동일한 이미지를 재현하는 데에만 유효하며, 프롬프트 자체가 변경되는 경우(감정 표현 교체)에는 생성 결과의 일관성을 보장하지 못한다는 근본적 한계를 확인했다. Seed는 확률적 노이즈의 초기값을 고정할 뿐, 프롬프트 변화에 따른 생성 결과의 분산을 제어하는 메커니즘이 아니기 때문이다.

이를 해결하기 위해 **Image-to-Image Generation** 방식을 도입했다. DEFAULT 감정 이미지를 `gemini-3-pro-image-preview` 모델로 먼저 생성하여 캐릭터의 시각적 정체성(헤어스타일, 얼굴형, 의상 등)을 정의하는 참조 이미지로 삼고, 나머지 10가지 감정 이미지들은 이 참조 이미지를 조건부 입력(init image)으로 삼아 동일 모델로 생성하는 구조를 채택했다.

이미지 프롬프트는 다섯 개 블록의 모듈형 조합으로 구성된다.
- **Style Block**: 소설 장르에 맞는 공통 화풍 키워드 (캐릭터 파싱 시 Gemini가 결정)
- **Look Block**: 캐릭터 파싱에서 추출된 5요소 외모 묘사 (정적, 감정 무관)
- **Emotion Block**: 감정별 사전 설계된 표정·자세 프롬프트 (10가지)
- **Framing Block**: `full body shot, front view, facing forward, looking at viewer` (전신 고정 구도)
- **Background Block**: `solid white background` (배경 제거 후처리 효율화)

모든 이미지 생성은 `gemini-3-pro-image-preview` 기반의 Gemini Batch API를 활용하여 병렬 처리한다. 생성 완료 후 Photoroom API를 통해 배경을 제거하여 투명 배경(Alpha Channel) PNG를 생성한다.

#### 3.3.2 배경 이미지 생성

배경 이미지는 씬 파싱에서 추출된 `description`을 기반으로 `gemini-3-pro-image-preview` 모델을 통해 16:9 비율, 2K 해상도로 생성된다. `timeOfDay`는 씬별로 다르므로 배경 자체의 묘사에는 포함하지 않는 설계를 적용했다.

### 3.4 BGM 생성

Google Lyria 3 Clip을 활용하여 씬 파싱 시 결정된 BGM 카테고리(ACTION, ROMANCE, MYSTERY, PEACEFUL, SAD, EPIC, DARK)와 30단어 이내의 영어 프롬프트를 기반으로 음악 클립을 생성한다. 루프 재생을 위해 `loopable structure, seamless loop` 지시문을 프롬프트에 자동으로 삽입한다.

### 3.5 VN Script 생성 및 프론트엔드 플레이어

#### 3.5.1 VN Script 생성

`EpisodeService.buildVnScript()`는 `scenes.json`의 `currentScreen` 배열을 이전 프레임과 비교하는 **diff 방식**으로 캐릭터 등장·퇴장·이동·감정 변화 명령을 생성한다. 이를 통해 불필요한 `show`/`hide` 명령을 최소화하여 프론트엔드 처리를 최적화했다. 특정 감정 이미지 생성 실패 시 DEFAULT 이미지로 자동 폴백하는 방어 로직도 포함된다.

#### 3.5.2 프론트엔드 커스텀 VN 엔진

외부 라이브러리 없이 직접 구현된 커스텀 VN 엔진을 `player.html`에 탑재했다. 메인 대시보드(`index.html`)와 iframe + postMessage 방식으로 통신하여 완전한 컨텍스트 격리를 실현했다. 주요 기능은 다음과 같다.

- **타이프라이터 효과**: 25ms 간격 한 글자씩 출력, 클릭 시 즉시 완성
- **화자 하이라이트**: 발화 캐릭터는 `brightness(1.0) + scale(1.02)`, 나머지는 `brightness(0.5)`
- **BGM 연속 재생**: 씬 전환 시 BGM이 변경될 때만 교체하여 음악적 연속성 유지
- **캐릭터 등장/퇴장 애니메이션**: CSS 트랜지션 기반의 페이드 인/아웃 연출

## 4. 연구 결과 및 평가 (Methodology and Evaluation)

### 4.1 평가 설계

N2VN 파이프라인의 출력 품질을 측정하기 위해 **사용자 대상 정성적 설문 평가**를 수행하였다. 평가 대상은 20대 대학생 11명으로 구성하였으며, 동일한 웹소설 에피소드(1,200자 분량)를 ① 원문 텍스트 형태, ② N2VN으로 변환된 비주얼 노벨 형태로 각각 경험한 뒤 설문에 응답하도록 하였다.

평가 지표는 다음 네 가지로 구성하였으며, 각 항목에 대해 5점 리커트 척도(1: 매우 불만족 ~ 5: 매우 만족)로 응답을 수집하였다.

| 평가 항목 | 설명 |
|---|---|
| Q1. 시각적 일관성 | 동일 캐릭터의 일러스트가 감정 변화 후에도 같은 인물로 인식되는 정도 |
| Q2. 맥락 조화도 | 생성된 배경 이미지 및 BGM이 해당 장면의 텍스트 분위기와 어울리는 정도 |
| Q3. 연출 자연스러움 | 캐릭터 등장·퇴장, 대사 연출 흐름이 자연스러운 정도 |
| Q4. 몰입감 향상 | 단순 텍스트 열람 대비 비주얼 노벨 형태에서 느끼는 몰입감 향상 정도 |

## 5. 토론 및 전망 (Discussion and Future Work)

### 5.1 연구 성과 정리

본 연구는 소설 텍스트를 입력으로 받아 캐릭터 이미지, 배경 이미지, BGM, 대화 스크립트를 자동으로 생성하고 웹 브라우저에서 즉시 플레이 가능한 비주얼 노벨로 출력하는 완전 자동화 파이프라인을 성공적으로 구현했다. 핵심 기술적 기여는 다음과 같다.

**다단계 LLM 파싱 설계**: 복잡한 소설 분석 과제를 캐릭터 파싱 → 씬 파싱의 두 단계로 분해하여 각 단계의 LLM 입력을 단순화하고 오류 전파 범위를 제한했다. tempId 패턴을 통해 씬 파싱 내의 신규 에셋 선언과 참조를 단일 LLM 호출로 처리하는 방법론을 고안했다.

**DEFAULT-First Image-to-Image 전략**: 이론상 유효할 것으로 예상했던 Seed 고정 방식의 한계를 실험적으로 확인하고, Image-to-Image 생성 방식으로 전환하여 캐릭터 일관성을 실질적으로 향상시켰다. 이는 VN 에셋 자동 생성 도메인에서의 실용적 전략을 제시한 사례다.

**이벤트 기반 비동기 파이프라인**: NestJS의 EventEmitter2를 활용하여 씬 파싱 완료 이후 캐릭터 이미지·배경 이미지·BGM 생성이 동시에 병렬 처리되는 구조를 구현했다. 이를 통해 전체 파이프라인의 실행 시간을 최소화했다.

### 5.2 한계 및 개선 방향

**캐릭터 일관성 강화**: 현재의 Image-to-Image 방식은 감정 변형 시 캐릭터 정체성의 완전한 보존을 보장하지 못한다. 향후 LoRA(Low-Rank Adaptation) Fine-tuning 또는 IP-Adapter 방식을 도입하여 캐릭터별 고정 임베딩을 학습하는 방향이 유력한 개선안이다.

**연출 품질 향상**: 현재 LLM이 화면 배치와 캐릭터 등장·퇴장을 결정하는 방식에는 비자연스러운 전환이 발생하는 케이스가 있다. 화면 상태 전이에 대한 더 정교한 프롬프트 설계 또는 후처리 스무딩 로직 도입이 필요하다.

**파이프라인 진행 상황 실시간 조회**: 현재 에피소드 생성 중 진행 상황을 클라이언트가 알 수 없다. WebSocket 또는 SSE(Server-Sent Events)를 도입하여 각 파이프라인 단계의 완료 여부를 실시간으로 전송하는 기능이 필요하다.

**소설 업로드 UI**: 현재 `novel.txt`를 AWS S3에 수동으로 업로드해야 하는 운영상 불편함이 있다. 파일 업로드 API 엔드포인트와 사용자 친화적 UI를 추가하면 완전한 엔드-투-엔드 사용자 경험을 제공할 수 있다.

**시리즈 연재 구조 확장**: 현재 에피소드 단위의 변환이 완성되어 있다. 이를 시리즈 구독, 회차별 열람, 플랫폼 로그인 기반 큐레이션 등의 플랫폼 기능으로 확장하면 제안서에서 목표로 한 '웹툰형 비주얼 노벨 플랫폼'에 한 걸음 더 다가설 수 있다.

### 5.3 결론

본 연구는 텍스트 소설과 플레이 가능한 비주얼 노벨 사이의 제작 비용 장벽을 생성형 AI 파이프라인으로 허무는 것이 기술적으로 실현 가능함을 증명했다. 특히 몰입감 향상(평균 4.36/5)이라는 사용자 평가 결과는, 현재의 AI 이미지 품질 수준에서도 단순 텍스트 열람 대비 의미 있는 경험 향상이 가능함을 실증한다. 캐릭터 일관성 문제가 핵심 과제로 남아 있지만, 이는 현재 학계에서도 가장 활발히 연구되는 분야인 만큼 기술 발전에 따라 급격히 개선될 수 있을 것으로 전망한다.
